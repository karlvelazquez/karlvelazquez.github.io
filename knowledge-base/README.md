# Knowledge Base — Folder Guide

This is a research/archiving project, not site content. It's a structured set of notes, renamed photos, and archived web content about Karl Velazquez, meant for later reference by Karl or by other LLMs/agents working on his behalf. Nothing here is meant to be published as-is.

## Structure

- **`images/`** — The 27 personal photos that were sitting loose in the repo root, copied in and renamed to descriptive kebab-case filenames (originals deleted from the root). `images/MANIFEST.md` has the full catalog: original filename → new filename → caption → best-guess context cross-reference. Guesses are labeled as guesses; several photos have "context unclear" where no confident match was found.

- **`research/`** — One file per resume experience (MIT d'Arbeloff Lab, Capital One, the Decaf compiler project, Apple internship, Phi Kappa Psi/Theta Tau, Mobius Industries), going beyond the resume bullets with actual background research on the relevant institutions, technologies, and conferences.

- **`publications/`** — Archived content from the web links provided: GitHub profile, LinkedIn (full content supplied by Karl directly, since live automated access remains blocked), the RSS 2025 project website, the arXiv preprint, the RSS 2025 program page, the Nature paper (full text, supplied by Karl), the two RSS/Nature code repos on GitHub, a YouTube video, and two MIT News/Alumni articles. Each file notes its source URL at the top and whether the content is full text, an AI-summarized extract, or partially blocked.

- **`instagram/`** — What little is accessible from Karl's Instagram profile (follower counts, location tag) given that Instagram blocks unauthenticated scraping of actual post content.

- **`BIO.md`** — The consolidated synthesis: a single narrative document pulling together background, education, career, publications, teaching, extracurriculars, high school activities, and hobbies, plus a "Gaps" section flagging things worth clarifying or adding.

## Known limitation

None of the tools used here can do a true browser "print to PDF" of a live webpage — archived pages are text/markdown extracts (sometimes AI-summarized rather than raw HTML), not pixel-perfect snapshots. If an exact visual copy of a page is ever needed, it would have to be captured manually.
